Break Glass Scripts

PowerShell 7+ Emergency Use Network Segment Identity Segment OT Staged — Not Yet Deployed

The Zero Networks Break Glass scripts provide emergency access recovery when Zero Networks Segment Server, the portal, or IdP is unavailable or blocking critical access. They directly modify firewall rules, WFP filters, and (for OT) network switch ACLs on targeted assets to restore connectivity.

Staged version — not yet deployed This document covers the v.Next version of BreakGlass.ps1, which has not yet been deployed to Segment Servers. The currently-deployed version is documented in breakglass-reference.html. Key additions in this version: nftables Linux backend, expanded Privileged-mode port sets for both Windows and Linux.
Pre-installed scripts — not part of ZNTools The scripts documented here (BreakGlass.ps1 and OTBreakGlass.ps1) are bundled with the Zero Networks installer and are pre-installed on all Segment Servers at C:\Program Files\Zero Networks\Breakglass\. They are not distributed through the ZNTools PowerShell module. This document is a reference for those pre-installed scripts.
Warning These scripts bypass Zero Networks segmentation controls. Use only when the Zero Networks Cloud Break Glass feature is unavailable and immediate access is required. Document and audit every use.

Prerequisites

RequirementDetails
PowerShell version7.0 or higher (#Requires -Version 7)
POSH-SSH moduleRequired for Linux operations. Script auto-installs from the internet or falls back to the bundled posh-ssh.3.1.1.nupkg.
segmentedAssets.jsonAuto-generated and routinely updated by the Zero Networks Segment Server. Located at C:\Program Files\Zero Networks\Breakglass\segmentedAssets.json. Required for bulk operations; not read for single-asset (-Asset / -IPAddress) runs. Do not edit manually.
Windows credentialsAccount with WinRM/PSRemoting access to target asset(s). When omitted, the script reads ForestsConfig from segmentedAssets.json and prompts once per domain and once per OU that has OuCredentials configured. Supply -ADUserName / -ADSvcPassword to override with a single explicit credential for all targets, or use -Credential with Get-Credential / Import-Clixml for interactive or headless runs.
Linux credentialsLinux service account with sudo su access on target assets. Use -LinuxUserName / -LinuxSvcPassword for password auth, or -LinuxUseSSHKey to supply an SSH key path at runtime.
Network accessRequired ports (WinRM TCP 5985/5986 for Windows; SSH TCP 22 for Linux) are automatically provisioned to Segment Servers, which is where this script is intended to run.
Linux firewall backendThe script supports both iptables (via python-iptables) and nftables (via python-nftables). For bulk operations, the backend is read from the AppliedFirewallType field in segmentedAssets.json. For single-asset operations, both backends are attempted automatically.

When to Use

Prefer the Zero Networks portal Cloud Break Glass in all normal scenarios. Use these scripts only when:

  • The Zero Networks management plane is unreachable.
  • Cloud Break Glass cannot be triggered fast enough for a production incident.
  • You need to target a specific asset that is not visible in the portal.
  • OT switch ACLs must be removed and no portal access is available.

BreakGlass.ps1

Windows Linux Emergency

Synopsis

Restores network and/or identity access to segmented Windows and Linux assets by remotely modifying firewall rules, WFP filters, and Group Policy on each target. Linux assets are handled via either iptables or nftables depending on the firewall backend in use on each host.

Syntax

-- Windows assets (bulk) -- .\BreakGlass.ps1 -Windows -Mode { Privileged | All } [-Network] [-Identity] [-ServersOnly] [-DisableBlockRule] [-ADUserName <string>] [-ADSvcPassword <string>] [-Credential <PSCredential>] [-DeploymentClusterName <string>]
-- Linux assets (bulk) -- .\BreakGlass.ps1 -Linux -Mode { Privileged | All } [-Network] [-LinuxUseSSHKey] [-ServersOnly] [-LinuxUserName <string>] [-LinuxSvcPassword <string>] [-DeploymentClusterName <string>]
-- Windows AND Linux assets (bulk) -- .\BreakGlass.ps1 -WindowsAndLinux -Mode { Privileged | All } [-Network] [-Identity] [-LinuxUseSSHKey] [-ServersOnly] [-DisableBlockRule] [-ADUserName <string>] [-ADSvcPassword <string>] [-Credential <PSCredential>] [-LinuxUserName <string>] [-LinuxSvcPassword <string>] [-DeploymentClusterName <string>]
-- Single asset by name -- .\BreakGlass.ps1 -Asset <string> { -Windows | -Linux } -Mode { Privileged | All } [-Network] [-Identity] [-LinuxUseSSHKey] [-ADUserName <string>] [-ADSvcPassword <string>] [-Credential <PSCredential>] [-LinuxUserName <string>] [-LinuxSvcPassword <string>]
-- Single asset by IP address -- .\BreakGlass.ps1 -IPAddress <string> { -Windows | -Linux } -Mode { Privileged | All } [-Network] [-Identity] [-ADUserName <string>] [-ADSvcPassword <string>] [-Credential <PSCredential>]

Parameters

-Windows

Targets Windows assets. Required when operating in the Windows parameter set. Mutually exclusive with -Linux; use -WindowsAndLinux to target both.

Type:Switch
Required:True (in Windows set)
Position:Named
Default:None
Pipeline input:False
-Linux

Targets Linux assets. Required when operating in the Linux parameter set.

Type:Switch
Required:True (in Linux set)
Position:Named
Default:None
Pipeline input:False
-WindowsAndLinux

Targets both Windows and Linux assets in a single run. Collects both AD and Linux credentials before processing.

Type:Switch
Required:True (in WindowsAndLinux set)
Position:Named
Default:None
Pipeline input:False
-Mode

Controls which firewall ports are opened on each target. Required whenever -Network is specified.

ValueWindows effectLinux effect
Privileged Opens inbound TCP 3389 (RDP), 5985 (WinRM), 5986 (WinRM HTTPS), 9389 (ADWS), 445 (SMB) via Windows Firewall and WFP. All outbound allowed. Opens inbound TCP 22 (SSH), 23 (Telnet), 445 (SMB) via iptables or nftables. All outbound allowed.
All Opens all inbound and outbound traffic via Windows Firewall and WFP. Accepts all inbound and outbound traffic via iptables or nftables.
Type:String
Required:Required with -Network
Accepted values:Privileged, All
Pipeline input:False
-Network

Triggers network segmentation break glass. Adds Windows Firewall and WFP allow rules (Windows) or iptables/nftables ACCEPT rules (Linux). Must be combined with -Mode. Only runs on assets where IsNetworkSegmented is $true.

Type:Switch
Required:Optional
Default:False
Pipeline input:False
-Identity

Triggers identity segmentation break glass on Windows assets. Exports the current security policy (secedit), removes all ZeroNetworks* local groups from User Rights assignments, re-applies the policy, and forces a Group Policy update. Only runs on assets where IsIdentitySegmented is $true.

Note Available for Windows and WindowsAndLinux parameter sets only. Not applicable to Linux assets.
Type:Switch
Required:Optional
Default:False
Pipeline input:False
-ServersOnly

Restricts the asset list to servers (type = 2 in segmentedAssets.json). Workstations and clients are skipped. Not available in the Asset or IP parameter sets since those already target a single asset explicitly.

Type:Switch
Required:Optional
Default:False
Pipeline input:False
-DisableBlockRule

On Windows, also disables all enabled Windows Firewall block rules and removes any WFP explicit-block filters installed by Zero Networks. Use this when the standard allow rules are still being overridden by block rules.

Warning This disables all block rules currently active on the target host, not only Zero Networks rules. Use with caution.
Type:Switch
Required:Optional
Default:False
Pipeline input:False
-Asset

Targets a single asset by hostname or FQDN. The value is resolved via DNS; a valid A record must exist. segmentedAssets.json is not read for single-asset runs. Mutually exclusive with -IPAddress and the bulk parameter sets.

Type:String
Required:True (in Asset set)
Position:Named
Pipeline input:False
-IPAddress

Targets a single asset by IP address. The IP is resolved via a DNS PTR lookup; a valid PTR record must exist. segmentedAssets.json is not read for single-asset runs. Mutually exclusive with -Asset.

Type:String
Required:True (in IP set)
Position:Named
Pipeline input:False
-Credential

A PSCredential used to connect to Windows assets via WinRM. Supply an explicit credential (for example, (Get-Credential)) or load one from disk with Import-Clixml. Cannot be combined with -ADUserName / -ADSvcPassword. When provided, it is used for all Windows targets and the domain/OU prompt flow is skipped.

Type:PSCredential
Required:Optional
Windows only:Yes
Pipeline input:False
-ADUserName

Active Directory credential username used to connect to Windows assets via WinRM. Accepted formats: DOMAIN\username or username@domain.com. Must be paired with -ADSvcPassword and cannot be combined with -Credential. If omitted, the script reads ForestsConfig from segmentedAssets.json and prompts once per primary domain, once per secondary domain, and once per OU that has OuCredentials configured. When an asset has an OrganizationalUnit value, the OU-specific credential is tried first, then the script falls back to the domain-level credential.

Type:String
Required:Optional
Must pair with:-ADSvcPassword
Pipeline input:False
-ADSvcPassword

Plain-text password for the AD account specified in -ADUserName. Must be used together with -ADUserName and cannot be combined with -Credential. The value is converted to a SecureString internally before use.

Type:String
Required:Optional
Must pair with:-ADUserName
Pipeline input:False
-LinuxUseSSHKey

When present, the script uses an SSH private key file instead of a password to authenticate against Linux assets. The script will prompt interactively for the path to the key file at runtime.

Type:Switch
Required:Optional
Default:False (password auth)
Pipeline input:False
-LinuxUserName

SSH username for Linux assets. Must be paired with -LinuxSvcPassword (or -LinuxUseSSHKey). If omitted, the user is prompted at runtime.

Type:String
Required:Optional
Pipeline input:False
-LinuxSvcPassword

Plain-text SSH password for the Linux user. Must be used together with -LinuxUserName. Cannot be combined with -LinuxUseSSHKey.

Type:String
Required:Optional

-DeploymentClusterName

Limits the asset scope to a single Zero Networks deployment cluster. The value is matched case-insensitively against cluster names in segmentedAssets.json. Tab-completion is supported — press Tab to cycle through available cluster names. If omitted, all clusters are included. Not available in the Asset or IP parameter sets.

Type:String
Required:Optional
Tab-complete:Yes
Pipeline input:False

Examples

Example 1 Open privileged ports on all Windows assets (network segment) 
PS> .\BreakGlass.ps1 -Windows -Mode Privileged -Network
Connects to every Windows asset in segmentedAssets.json that has network segmentation active. Opens inbound TCP 3389, 5985, 5986, 9389, and 445 via Windows Firewall and WFP. Credentials are prompted interactively per AD domain (and per OU if configured).
Example 2 Open all ports on Linux servers using SSH key 
PS> .\BreakGlass.ps1 -Linux -LinuxUseSSHKey -Network -Mode All -ServersOnly
Targets only Linux server-type assets. Uses an SSH key for authentication (path prompted at runtime). Each asset's AppliedFirewallType from segmentedAssets.json determines whether iptables or nftables is used. Inserts an ACCEPT-all rule on each target.
Example 3 Single Linux server by hostname using SSH key 
PS> .\BreakGlass.ps1 -Asset linuxserver.contoso.local -Linux -LinuxUseSSHKey -Network -Mode All
Resolves linuxserver.contoso.local via DNS and runs break glass against that single host. Because the firewall type is unknown for a manually-specified asset, both iptables and nftables backends are attempted. A failure on one backend does not abort the other. The SSH key path is prompted interactively.
Example 4 Single Windows asset by IP address (interactive credentials) 
PS> .\BreakGlass.ps1 -IPAddress 1.1.1.1 -Windows -Network -Mode All
Resolves 1.1.1.1 via a PTR record, then prompts interactively for a domain name and AD username before opening all ports on the target.
Example 5 Single Windows asset by IP address (explicit credentials) 
PS> .\BreakGlass.ps1 -IPAddress 1.1.1.1 -Windows -Network -Mode All `
         -ADUserName contoso.local\Administrator -ADSvcPassword P@ssw0rd
Same as Example 4 but supplies credentials non-interactively. Suitable for scripted or automated break glass runbooks.
Example 6 Bulk Windows run using Get-Credential 
PS> .\\BreakGlass.ps1 -Windows -Network -Mode All -Credential (Get-Credential)
Prompts for credentials once and uses the resulting PSCredential for all Windows targets. This bypasses per-domain and per-OU prompts from segmentedAssets.json.
Example 7 Headless Windows run using Export-Clixml / Import-Clixml 
PS> Get-Credential | Export-Clixml -Path C:\\secure\\breakglass-cred.xml
PS> .\\BreakGlass.ps1 -Windows -Network -Mode All -Credential (Import-Clixml -Path C:\\\\secure\\\\breakglass-cred.xml)
Exports a credential once, then reuses it in a headless run. The encrypted CLIXML can only be decrypted by the same Windows user on the same machine.
Example 8 Scope to a single deployment cluster 
PS> .\BreakGlass.ps1 -Windows -Mode All -Network -DeploymentClusterName "zero.local"
Restricts the affected asset pool to the zero.local deployment cluster only. Assets in other clusters are skipped entirely. Use Tab to cycle through available cluster names.

Outputs

The script writes two text files to the current directory on completion:

FileContents
success_list.txtOne FQDN per line for every asset successfully processed.
failed_list.txtOne FQDN + error message per line for every asset that failed.

Console output shows connection status, applied rules, and any warnings in real time as each asset is processed (up to 100 assets in parallel).

OTBreakGlass.ps1

OT Cisco IOS-XE Emergency Unchanged

OTBreakGlass.ps1 is unchanged from the currently deployed version. See breakglass-reference.html for full documentation.

Synopsis

Removes Zero Networks ACLs and optionally NetFlow monitoring from Cisco IOS-XE switch interfaces via RESTCONF, restoring unrestricted traffic flow on OT network segments.

Syntax

.\OTBreakGlass.ps1 [-SwitchPassword <SecureString>] [-RemoveMonitoring]

Parameters

-SwitchPassword

A single shared password for all switches (SecureString). If omitted, the script prompts per switch.

Type:SecureString
Required:Optional
-RemoveMonitoring

Also removes Zero Networks NetFlow monitoring from switch interfaces. Without this switch, only ACLs are removed.

Type:Switch
Required:Optional

Examples

Example 1 Remove ACLs only (prompt per switch) 
PS> .\OTBreakGlass.ps1
Reads all switches from switches.json and removes zeroNetworks* ACLs from all interfaces.
Example 2 Remove ACLs and monitoring (shared password) 
PS> .\OTBreakGlass.ps1 -RemoveMonitoring -SwitchPassword (Read-Host "Switch password" -AsSecureString)
Uses a single shared password and additionally removes Zero Networks NetFlow monitors.

Mode Reference

ModeOSMechanismResult
Privileged Windows Windows Firewall + WFP Inbound TCP 3389 (RDP), 5985 (WinRM), 5986 (WinRM HTTPS), 9389 (ADWS), 445 (SMB) allowed; all outbound allowed
All Windows Windows Firewall + WFP All inbound and outbound traffic allowed
Privileged Linux iptables or nftables (per AppliedFirewallType) Inbound TCP 22 (SSH), 23 (Telnet), 445 (SMB) ACCEPT; all outbound ACCEPT
All Linux iptables or nftables (per AppliedFirewallType) ACCEPT all rule inserted in INPUT and OUTPUT chains

Notes

  • Rules and filters added by the break glass scripts are persistent across reboots. They must be manually removed or will be cleaned up when the Zero Networks agent next synchronises policy.
  • For Windows assets the script uses PowerShell Remoting (WinRM) with Negotiate authentication. Ensure WinRM is enabled and accessible on targets.
  • For Linux assets the script connects via SSH using the POSH-SSH module, escalates to root with sudo su, and manipulates the firewall through a Zero Networks Python virtual environment bundled on the asset. Both iptables (via python-iptables) and nftables (via python-nftables) backends are supported. For bulk operations, the backend is selected from AppliedFirewallType in segmentedAssets.json. For single-asset operations (-Asset / -IPAddress), both backends are attempted; a failure on one does not abort the other.
  • Both scripts create success_list.txt and failed_list.txt (or ot_success_list.txt / ot_failed_list.txt for OT) in the working directory.
  • Bulk operations run with -ThrottleLimit 100 (up to 100 assets processed concurrently).
  • segmentedAssets.json is only loaded for bulk operations. Single-asset runs (-Asset / -IPAddress) do not read the inventory file.
  • The segmentedAssets.json file is automatically generated and kept up to date by the Zero Networks Segment Server. It is read from C:\Program Files\Zero Networks\Breakglass\ on the machine running the script. Do not edit it manually.
  • For OT, switch credentials are never stored; they are held in memory only for the duration of the script run and cleared afterwards.

Change Manifest

vs. Deployed Version

Functional changes in this version of BreakGlass.ps1 relative to the currently-deployed script documented in breakglass-reference.html.

AreaChangeImpact
Linux firewall backend Added nftables support alongside iptables. The backend is selected per-asset from AppliedFirewallType in segmentedAssets.json for bulk operations. Required for modern Linux distributions (e.g. RHEL 10) that ship without iptables-legacy.
Single-asset Linux (-Asset / -IPAddress) Both iptables and nftables backends are now attempted automatically in sequence. Each attempt is isolated; a failure on one backend does not abort the other. Eliminates the need to know which backend is active when targeting a single Linux host manually.
Linux Privileged mode ports Expanded from SSH (22) only to SSH (22), Telnet (23), and SMB (445) via multiport match. Restores management access for environments that require SMB or legacy Telnet alongside SSH.
Windows Privileged mode ports Expanded from RDP (3389) only to RDP (3389), WinRM HTTP (5985), WinRM HTTPS (5986), ADWS (9389), and SMB (445). Applied at both the Windows Firewall and WFP layers. Enables PSRemoting, AD management tooling, and file access in a single Privileged-mode run — previously a second -Mode All run was needed to restore WinRM access.
segmentedAssets.json loading The inventory file is now only loaded for bulk operations. Single-asset runs (-Asset / -IPAddress) skip the load entirely. Avoids a misleading error if the JSON is stale or absent when targeting a known asset directly.
