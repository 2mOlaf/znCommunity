Break Glass Scripts

PowerShell 7+ Emergency Use Network Segment Identity Segment OT Staged — Not Yet Deployed

The Zero Networks Break Glass scripts provide emergency access recovery when Zero Networks Segment Server, the portal, or IdP is unavailable or blocking critical access. They directly modify firewall rules, WFP filters, and (for OT) network switch ACLs on targeted assets to restore connectivity.

Staged version — not yet deployed This document covers the v.Next version of BreakGlass.ps1, which has not yet been deployed to Segment Servers. The currently-deployed version is documented in breakglass-reference.html. Key additions in this version: programmatic SSH key path for Linux (-LinuxSSHKeyPath), Get-Credential prompts replacing Read-Host, and fixes to the -ADSvcPassword and -LinuxSvcPassword parameter types.
Pre-installed scripts — not part of ZNTools The scripts documented here (BreakGlass.ps1 and OTBreakGlass.ps1) are bundled with the Zero Networks installer and are pre-installed on all Segment Servers at C:\Program Files\Zero Networks\Breakglass\. They are not distributed through the ZNTools PowerShell module. This document is a reference for those pre-installed scripts.
Warning These scripts bypass Zero Networks segmentation controls. Use only when the Zero Networks Cloud Break Glass feature is unavailable and immediate access is required. Document and audit every use.
Breaking Changes in this version

Two parameters have a type change relative to the currently-deployed version. If you have automation runbooks that pass these parameters, review them before deploying.

  • -ADSvcPassword — type changed from [SecureString] to [string]. Note: the previous [SecureString] declaration was a bug; passing a plain-text string was silently coerced to a SecureString at bind time and then double-converted to the literal string "System.Security.SecureString" as the password, causing authentication failures. The programmatic path was effectively non-functional in the prior version. No working caller is broken by this change.
  • -LinuxSvcPassword — same type change and same root cause.
Deprecations in this version

The following usage pattern still works but emits a Write-Warning at runtime. It will be removed in a future version.

  • Using -LinuxUseSSHKey without -LinuxSSHKeyPath — the script still falls back to a Read-Host prompt for the SSH key file path, but emits a deprecation warning. Pair with -LinuxSSHKeyPath to suppress the warning and supply the path non-interactively.

When to Use

Prefer the Zero Networks portal Cloud Break Glass in all normal scenarios. Use these scripts only when:

  • The Zero Networks management plane is unreachable.
  • Cloud Break Glass cannot be triggered fast enough for a production incident.
  • You need to target a specific asset that is not visible in the portal.
  • OT switch ACLs must be removed and no portal access is available.

BreakGlass.ps1

Windows Linux Emergency

Synopsis

Restores network and/or identity access to segmented Windows and Linux assets by remotely modifying firewall rules, WFP filters, and Group Policy on each target. Linux assets are handled via either iptables or nftables depending on the firewall backend in use on each host.

Syntax

-- Windows assets (bulk) -- .\BreakGlass.ps1 -Windows -Mode { Privileged | All } [-Network] [-Identity] [-ServersOnly] [-DisableBlockRule] [-ADUserName <string>] [-ADSvcPassword <string>] [-DeploymentClusterName <string>]
-- Linux assets (bulk) -- .\BreakGlass.ps1 -Linux -Mode { Privileged | All } [-Network] [-LinuxUseSSHKey] [-LinuxSSHKeyPath <string>] [-ServersOnly] [-LinuxUserName <string>] [-LinuxSvcPassword <string>] [-DeploymentClusterName <string>]
-- Windows AND Linux assets (bulk) -- .\BreakGlass.ps1 -WindowsAndLinux -Mode { Privileged | All } [-Network] [-Identity] [-LinuxUseSSHKey] [-LinuxSSHKeyPath <string>] [-ServersOnly] [-DisableBlockRule] [-ADUserName <string>] [-ADSvcPassword <string>] [-LinuxUserName <string>] [-LinuxSvcPassword <string>] [-DeploymentClusterName <string>]
-- Single asset by name -- .\BreakGlass.ps1 -Asset <string> { -Windows | -Linux } -Mode { Privileged | All } [-Network] [-Identity] [-LinuxUseSSHKey] [-LinuxSSHKeyPath <string>] [-ADUserName <string>] [-ADSvcPassword <string>] [-LinuxUserName <string>] [-LinuxSvcPassword <string>]
-- Single asset by IP address -- .\BreakGlass.ps1 -IPAddress <string> { -Windows | -Linux } -Mode { Privileged | All } [-Network] [-Identity] [-ADUserName <string>] [-ADSvcPassword <string>]

-Mode

Controls which firewall ports are opened on each target. Required whenever -Network is specified.

ValueWindows effectLinux effect

Limits the asset scope to a single Zero Networks deployment cluster. Matched case-insensitively against cluster names in segmentedAssets.json. Tab-completion is supported. If omitted, all clusters are included. Not available in the Asset or IP parameter sets.

Type:String
Required:Optional
Tab-complete:Yes
Pipeline input:False

Examples

Example 1 Open privileged ports on all Windows assets (interactive credentials) 
PS> .\BreakGlass.ps1 -Windows -Mode Privileged -Network
Connects to every Windows asset in segmentedAssets.json that has network segmentation active. Credentials are collected via Get-Credential — once per AD domain (and per OU if configured). The username field is pre-filled from ForestsConfig.
Example 2 Open all ports on Windows assets (explicit credentials) 
PS> .\BreakGlass.ps1 -Windows -Network -Mode All `
         -ADUserName contoso.local\Administrator -ADSvcPassword P@ssw0rd
Supplies credentials non-interactively. -ADSvcPassword now accepts a plain-text string. Suitable for automated break glass runbooks.
Example 3 Open all ports on Linux servers using SSH key (programmatic) 
PS> .\BreakGlass.ps1 -Linux -LinuxUseSSHKey -LinuxSSHKeyPath "C:\keys\zn_breakglass.pem" `
         -LinuxUserName znbg -Network -Mode All -ServersOnly
Supplies the SSH key path directly via -LinuxSSHKeyPath — no interactive prompt, no deprecation warning. Each asset's AppliedFirewallType determines whether iptables or nftables is used.
Example 4 Open all ports on Linux servers using SSH key (interactive — deprecated) 
PS> .\BreakGlass.ps1 -Linux -LinuxUseSSHKey -Network -Mode All -ServersOnly
Same operation without -LinuxSSHKeyPath. The script falls back to a Read-Host prompt and emits a deprecation warning. Add -LinuxSSHKeyPath to suppress the warning.
Example 5 Single Linux server by hostname — SSH key, fully non-interactive 
PS> .\BreakGlass.ps1 -Asset linuxserver.contoso.local -Linux -LinuxUseSSHKey `
         -LinuxSSHKeyPath "C:\keys\zn_breakglass.pem" -LinuxUserName znbg -Network -Mode All
Resolves linuxserver.contoso.local via DNS and runs break glass against that single host. Both iptables and nftables backends are attempted automatically. No prompts.
Example 6 Open privileged ports on Linux assets using password auth 
PS> .\BreakGlass.ps1 -Linux -Network -Mode Privileged `
         -LinuxUserName znbg -LinuxSvcPassword P@ssw0rd
Supplies Linux credentials non-interactively. Both -LinuxUserName and -LinuxSvcPassword must be provided to skip the Get-Credential prompt entirely.
Example 7 Scope to a single deployment cluster 
PS> .\BreakGlass.ps1 -Windows -Mode All -Network -DeploymentClusterName "zero.local"
Restricts the affected asset pool to the zero.local cluster only. Use Tab to cycle through available cluster names.

Outputs

The script writes two text files to the current directory on completion:

FileContents
success_list.txtOne FQDN per line for every asset successfully processed.
failed_list.txtOne FQDN + error message per line for every asset that failed.

Console output shows connection status, applied rules, and any warnings in real time as each asset is processed (up to 100 assets in parallel).

OTBreakGlass.ps1

OT Cisco IOS-XE Emergency Unchanged

OTBreakGlass.ps1 is unchanged from the currently-deployed version. See breakglass-reference.html for full documentation.

Synopsis

Removes Zero Networks ACLs and optionally NetFlow monitoring from Cisco IOS-XE switch interfaces via RESTCONF, restoring unrestricted traffic flow on OT network segments.

Syntax

.\OTBreakGlass.ps1 [-SwitchPassword <SecureString>] [-RemoveMonitoring]

Parameters

-SwitchPassword

A single shared password for all switches (SecureString). If omitted, the script prompts per switch.

Type:SecureString
Required:Optional
-RemoveMonitoring

Also removes Zero Networks NetFlow monitoring from switch interfaces. Without this switch, only ACLs are removed.

Type:Switch
Required:Optional

Examples

Example 1 Remove ACLs only (prompt per switch) 
PS> .\OTBreakGlass.ps1
Reads all switches from switches.json and removes zeroNetworks* ACLs from all interfaces.
Example 2 Remove ACLs and monitoring (shared password) 
PS> .\OTBreakGlass.ps1 -RemoveMonitoring -SwitchPassword (Read-Host "Switch password" -AsSecureString)
Uses a single shared password and additionally removes Zero Networks NetFlow monitors.

Notes

  • Rules and filters added by the break glass scripts are persistent across reboots. They must be manually removed or will be cleaned up when the Zero Networks agent next synchronises policy.
  • For Windows assets the script uses PowerShell Remoting (WinRM) with Kerberos authentication. Ensure WinRM is enabled and accessible on targets.
  • Interactive credential collection uses Get-Credential. On Windows GUI sessions this shows a credential dialog; on headless or console sessions it falls back to a text prompt. The username is pre-filled from ForestsConfig (Windows) or -LinuxUserName (Linux) when available.
  • For Linux assets the script connects via SSH using the POSH-SSH module, escalates to root with sudo su, and manipulates the firewall through a Zero Networks Python virtual environment bundled on the asset. Both iptables and nftables backends are supported; the backend is selected from AppliedFirewallType for bulk operations, or both are tried for single-asset runs.
  • Both scripts create success_list.txt and failed_list.txt in the working directory.
  • Bulk operations run with -ThrottleLimit 100 (up to 100 assets processed concurrently).
  • segmentedAssets.json is only loaded for bulk operations. Single-asset runs do not read the inventory file.
  • The segmentedAssets.json file is automatically generated by the Zero Networks Segment Server. It is read from C:\Program Files\Zero Networks\Breakglass\. Do not edit it manually.
  • For OT, switch credentials are never stored; they are held in memory only for the duration of the script run and cleared afterwards.

Change Manifest

vs. Current Deployed Version

Changes in this staged version relative to the currently-deployed version documented in breakglass-reference.html.

Breaking Changes

ParameterChangeMigration
-ADSvcPassword Type changed from [SecureString] to [string]. The prior declaration caused PowerShell to coerce a plain-text input to a SecureString at bind time, then convert it to the literal string "System.Security.SecureString" during processing — always producing the wrong credential. The parameter was non-functional in the current deployed version. Pass the password as a plain string. If your runbook first ran ConvertTo-SecureString "..." -AsPlainText -Force, remove that wrapper.
-LinuxSvcPassword Same type change and root cause as -ADSvcPassword. Same migration: pass the plain-text string directly.

Deprecations

Usage patternReasonReplacement
-LinuxUseSSHKey without -LinuxSSHKeyPath Relying on a Read-Host prompt for the SSH key path prevents unattended execution and is inconsistent with how all other credential inputs are handled. Add -LinuxSSHKeyPath "<path>". The interactive fallback still works but emits a Write-Warning.

New Features

AreaChangeImpact
-LinuxSSHKeyPath New parameter. Accepts the SSH private key file path as a string. When provided with -LinuxUseSSHKey, the interactive prompt is skipped entirely and no deprecation warning is emitted. Enables fully unattended Linux SSH-key-based break glass in automated runbooks.
Windows interactive credential collection The interactive path now calls Get-Credential instead of Read-Host -AsSecureString. The username field is pre-filled from ForestsConfig. Both username and password are collected in a single prompt per domain instead of two sequential Read-Host calls. On GUI sessions this shows a credential dialog.
Linux password interactive credential collection The interactive path now calls Get-Credential instead of separate Read-Host prompts. When only -LinuxUserName is provided, the username is pre-filled. Consistent with Windows behavior; one prompt collects both credentials.
Bug fix: $using:linuxSSHKey in parallel block The SSH key path variable was referenced as $global:linuxSSHKey inside the ForEach-Object -Parallel block, which is inaccessible from a parallel runspace. Corrected to $using:linuxSSHKey. SSH key-based Linux break glass now reliably passes the key path to each parallel SSH session. Previously the key path was always $null in parallel workers, causing every SSH session to fail.
