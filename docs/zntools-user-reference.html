ZNTools

PowerShell 7+ Module User Reference v1.5

ZNTools is a PowerShell module for Zero Networks operators. It provides network connectivity checks, Linux configuration profiles, segment server clusters, environment health data, security event rate and log-volume analysis, asset browser queries against local JSON snapshots, ZN service lifecycle management, and AD-to-ZN identity status sync.

Prefixing All commands are exported with the ZN prefix via the module manifest. Use Test-ZNPort, Get-ZNBGAsset, Invoke-ZNServices, etc.

Quick start

Install Directly from GitHub (PowerShell 7+) 
PS> irm https://raw.githubusercontent.com/2mOlaf/znCommunity/feature/zntools/Segment/Tools/ZNTools/install.ps1 | iex
PS> Import-Module ZNTools
Downloads and installs the module into your user PowerShell Modules path, then loads it.
Install From a local clone 
PS> Import-Module .\ZNTools\ZNTools.psd1
Install From a different fork/branch 
PS> & ([scriptblock]::Create((irm https://raw.githubusercontent.com/2mOlaf/znCommunity/feature/zntools/Segment/Tools/ZNTools/install.ps1))) -Repo zeronetworks/Community -Branch master
Useful once the module has merged upstream, or to test against another fork.
Extending ZNTools? If you want to add new commands or modify module internals, see the ZNTools Author Reference for the module structure, required patterns, and private helper documentation.

Authentication

API-backed commands use the ZN_API_KEY environment variable (a JWT). Override per command with -ApiKey and/or -ApiUrl. Asset browser commands work offline — no API key required after loading data.

Test-ZNPort

Networking Read-only

Synopsis

Tests TCP connectivity to a host/port and reports the source IP used.

Syntax

Test-ZNPort -Computer <string> -Port <int> [-Millisecond <int>] [-Continuous] [-PreferIPv4]

Parameters

-Computer

Target hostname or FQDN.

-Port

TCP port to test.

-Millisecond

Timeout in milliseconds. Default: 1000.

-Continuous

Continuous loop mode with live pass/fail output.

-PreferIPv4

Prefer IPv4 resolution and sockets.

Examples

Example 1 Single probe 
PS> Test-ZNPort -Computer server01 -Port 443
Performs one TCP connection attempt and returns an object with SourceIP and Success.
Example 2 Continuous IPv4-only checks 
PS> Test-ZNPort -Computer server01 -Port 22 -Continuous -PreferIPv4
Forces IPv4 resolution and prints live results until stopped with Ctrl+C.

Show-ZNHealthDashboard

Health Console Output

Synopsis

Displays a health dashboard for unhealthy assets and optionally exports CSV.

Syntax

Show-ZNHealthDashboard [-ApiKey <string>] [-ApiUrl <string>] [-ExportCsv <string>] [-IncludeNA] [-IncludeDisconnected] [-IncludeDisconnectedDays <int>] [-ThrottleLimit <int>] [-DeploymentsClusterId <string>]

Parameters

-IncludeNA

Include assets with an N/A health state — this also pulls in Not-Monitored and similar unmonitorable assets that a plain run leaves out. Because of that, this always fetches the full tenant asset list rather than the narrower non-healthy fetch the default path uses.

-IncludeDisconnected

Adds a disconnected-assets section to the report.

-IncludeDisconnectedDays

Only include assets disconnected for at least this many days. Implies -IncludeDisconnected. Default: 0 — any currently-disconnected asset counts.

-ThrottleLimit

Max concurrent per-asset health-detail lookups. Default: 20. The bulk asset list only carries a healthStatus code, not the remediation detail text (which firewall profile, which port rule) — getting that requires one API call per non-healthy asset, so this fans those calls out in parallel instead of one at a time. Lower this if the API starts rate-limiting on very large tenants.

-DeploymentsClusterId

Scope the whole report — health section and disconnected section alike — to one deployment cluster instead of the full tenant. Look up a cluster's ID with Get-ZNSegmentCluster.

-ExportCsv

Path to export the health (and, with -IncludeDisconnected, disconnected) rows as CSV.

Examples

Example 1 Health dashboard 
PS> Show-ZNHealthDashboard
Shows system health and unhealthy asset details.
Example 2 Include disconnected assets 
PS> Show-ZNHealthDashboard -IncludeDisconnected
Adds a disconnected assets section to the output.
Example 3 Export CSV 
PS> Show-ZNHealthDashboard -ExportCsv health.csv
Exports health rows to a CSV file.
Example 4 Scope to one cluster 
PS> Show-ZNHealthDashboard -DeploymentsClusterId 'C:d:00b0ceed' -IncludeDisconnected
Reports only the named cluster's assets — faster than a full-tenant run when you only care about one Segment Server deployment.
Example 5 Lower concurrency 
PS> Show-ZNHealthDashboard -ThrottleLimit 5
Reduces concurrent health-detail lookups — useful if the API starts responding with rate-limit errors on a very large tenant.

Get-ZNDisconnectedAssetMetric

Health Read-only Quiet / Scriptable

Synopsis

Reports disconnected ZN asset counts — overall and per deployment cluster — as metric objects suitable for feeding a time-series dashboard. It's the quiet, scriptable counterpart to Show-ZNHealthDashboard's -IncludeDisconnected section, sharing the same disconnected-asset detection logic (Get-ZNDisconnectedAsset) under the hood — though not the same asset source, see the callout below.

No banner, by design Unlike every other entry-point command in this module, this command does not display the ASCII banner or progress log lines. It's meant to run unattended on a schedule and feed a metrics pipeline — banner output would just be noise (or worse, get mixed into captured stdout) in that context. See the Banner guidance table for details.
Fetches from /assets/monitored, not the full tenant This command fetches only actively-monitored assets, excluding Not-Monitored and similar unmonitorable ones — roughly halving the fetch on a typical tenant, with no cluster dropping out of the per-cluster breakdown as a result. It does exclude a small number of Not-Monitored/Unmonitorable assets that still carry stale connection state (observed ~0.7% of disconnected assets on a test tenant) — accepted deliberately here, since an asset ZN isn't monitoring isn't actionable from this metric anyway. Show-ZNHealthDashboard's -IncludeDisconnected section does not take this shortcut — a Not-Monitored asset can still carry a real, non-N/A health status, and hiding that would defeat the point of a health dashboard. See the Author Guide for the full reasoning.

Syntax

Get-ZNDisconnectedAssetMetric [-ApiKey <string>] [-ApiUrl <string>] [-IncludeDisconnectedDays <int>]

Parameters

-IncludeDisconnectedDays

Only count assets disconnected for at least this many days. Default: 0 — any asset currently disconnected counts, regardless of how long. Same semantics as Show-ZNHealthDashboard -IncludeDisconnectedDays — tune this to match what the customer considers "disconnected" for their dashboard (e.g. filter out brief blips).

Output

One PSCustomObject per deployment cluster, plus a final TOTAL row summing all clusters. Assets with no Segment Server deployment cluster — e.g. Cloud Connector- or Lightweight Agent-monitored assets, which never get a deploymentsClusterId — get their own Unclustered (<monitor type>) row per monitoring mechanism (e.g. Unclustered (Cloud Connector)) instead of one flat Unclustered bucket. Every known cluster/monitor-type combination gets a row on every run — even at count 0 — so a series stays continuous rather than dropping out when it briefly has nothing disconnected.

PropertyDescription
TimestampCapture time for this batch — the same value across every row in a single run, so cluster rows and the TOTAL row correlate as one measurement.
ClusterIdDeployment cluster ID, or $null on Unclustered and TOTAL rows.
ClusterNameDeployment cluster name, Unclustered (<monitor type>), or TOTAL.
DisconnectedCountNumber of disconnected assets matching -IncludeDisconnectedDays.
DaysThresholdEcho of the -IncludeDisconnectedDays value used for this run.
On failure, expect nothing — not a zero If the API call fails, this command writes a terminating error and returns no objects at all, rather than a fabricated zero-count result. Treat a missing/empty result as "no data point this run" in your metrics pipeline, not as "zero disconnected assets" — otherwise a real outage could silently render as a healthy flat line on the dashboard.

Examples

Example 1 All clusters plus total 
PS> Get-ZNDisconnectedAssetMetric
Returns one object per cluster plus a TOTAL row for all currently-disconnected assets.
Example 2 Filter out brief blips 
PS> Get-ZNDisconnectedAssetMetric -IncludeDisconnectedDays 3
Only counts assets disconnected for 3+ days.
Example 3 Aggregate count only 
PS> Get-ZNDisconnectedAssetMetric | Where-Object ClusterName -eq 'TOTAL' | Select-Object -ExpandProperty DisconnectedCount
Extracts just the aggregate count, e.g. for a simple single-value metric push.
Example 4 JSON for a metrics endpoint 
PS> Get-ZNDisconnectedAssetMetric -IncludeDisconnectedDays 1 | ConvertTo-Json
Produces one JSON metric point per cluster (plus TOTAL) for a scheduled task to POST somewhere.

Invoke-ZNServices

Services Destructive

Synopsis

Stops, starts, or restarts all Zero Networks services (zn*) on the local machine, a single remote Segment Server, or every Segment Server discovered via the ZN API.

Requirements Local scope requires an Administrator session. Remote and AllServers scopes require WinRM (PSRemoting) to be enabled and reachable on each target Segment Server.

Syntax

Local (default) — requires AdministratorInvoke-ZNServices -Action <Stop|Start|Restart>
Remote — single Segment ServerInvoke-ZNServices -Action <Stop|Start|Restart> -ComputerName <string> [-Credential <PSCredential>]
AllServers — all Segment Servers via APIInvoke-ZNServices -Action <Stop|Start|Restart> -AllServers [-ClusterName <string>] [-Credential <PSCredential>] [-ApiKey <string>] [-ApiUrl <string>]

Parameters

-Action

Required. Stop, Start, or Restart.

-ComputerName

Hostname or IP of a single remote Segment Server. Enables the Remote parameter set.

-AllServers

Discover all Segment Servers from the ZN API and target each. Requires API access.

-ClusterName

With -AllServers: limit to Segment Servers in this cluster. Partial match, case-insensitive. Uses in-memory cluster data if Import-ZNBGAssetData has been run.

-Credential

PSCredential for PSRemoting. If omitted, the current session identity is used.

Examples

Example 1 Restart services locally 
PS> Invoke-ZNServices -Action Restart
Restarts all zn* services on the local machine. Requires Administrator.
Example 2 Restart on a single remote server 
PS> Invoke-ZNServices -Action Restart -ComputerName segment02.zero.local
Connects via PSRemoting and restarts services on the target server.
Example 3 Restart across all Segment Servers 
PS> Invoke-ZNServices -Action Restart -AllServers
Discovers all Segment Servers from the ZN API and restarts services on each.
Example 4 Stop services in a specific cluster 
PS> Invoke-ZNServices -Action Stop -AllServers -ClusterName "zero.local"
Limits the operation to Segment Servers in the zero.local cluster.

Get-ZNSecurityEventRate

Security Events Read-only Local

Synopsis

Shows average and peak rates per second for one or more Security-log Event IDs over a specified time period. Defaults to Windows Filtering Platform security events 5156 (permitted connection) and 5157 (blocked connection) — the original purpose of this command — but -EventId can target any other Event ID(s), including the Top N Event IDs surfaced by Get-ZNSecurityLogAnalysis.

Audit policy requirement Events are only logged when the matching audit subcategory is enabled in the local audit policy. If no events are found, check current policy with:
auditpol /get /category:*

Syntax

Get-ZNSecurityEventRate -Period <string> [-EventId <int[]>] [-ComputerName <string>] [-Credential <PSCredential>]

Parameters

-Period

Required. Time window to analyze. A positive integer followed by h (hours) or d (days) — for example: 1h, 4h, 24h, 1d, 7d.

Peak rate is computed from 1-second buckets for periods up to 1 hour and from 1-minute buckets (normalized to per-second) for longer periods.

-EventId

One or more Security-log Event IDs to measure. Default: 5156, 5157. Event IDs that Zero Networks segmentation depends on (see $script:ZNRequiredEventIds) are marked with * in the output table.

-ComputerName

Optional. Query a remote machine via WinRM (PSRemoting). The entire computation runs on the remote host — only the final numbers are returned across the wire, so no raw event objects are serialized. Requires the Windows Remote Management service to be running and reachable on the target.

-Credential

Optional PSCredential for the remote session. Only used with -ComputerName. If omitted, the current session identity is used.

Output

Displays a table with one row per requested Event ID plus a combined total row: event count, average events/sec, average KB/s, peak events/sec, and peak KB/s. Rows for Event IDs required by Zero Networks are suffixed with *, with a legend line below the table.

What KB/s measures The KB/s and MB/s values represent the Security event log write rate — how fast WFP audit data is being written to the Security log. This is useful for SIEM ingestion sizing and understanding audit overhead. It is not a measure of network traffic throughput. The rate is estimated by sampling up to 100 event XML payloads and multiplying average size by the events/sec rate.

Examples

Example 1 Last 1 hour 
PS> Get-ZNSecurityEventRate -Period 1h
Reports WFP event rates over the last hour using 1-second peak buckets.
Example 2 Last 4 hours 
PS> Get-ZNSecurityEventRate -Period 4h
Reports WFP event rates over the last 4 hours using 1-minute peak buckets normalized to per-second.
Example 3 Last 7 days 
PS> Get-ZNSecurityEventRate -Period 7d
Reports WFP event rates over the last 7 days. Useful for sizing and capacity planning.
Example 4 Remote — current identity 
PS> Get-ZNSecurityEventRate -Period 4h -ComputerName segment01.zero.local
Queries segment01 remotely via WinRM. All computation runs on the remote host; only the results are returned.
Example 5 Remote — explicit credential 
PS> $cred = Get-Credential
PS> Get-ZNSecurityEventRate -Period 1d -ComputerName segment01.zero.local -Credential $cred
Same as above but authenticates with explicit credentials — useful when the local session identity doesn't have remote access.
Example 6 Other Event IDs 
PS> Get-ZNSecurityEventRate -Period 1h -EventId 4688, 4689
Measures process creation/exit rates instead of the default WFP connection events.

Get-ZNSecurityLogAnalysis

Security Events Read-only Local / Remote / Offline

Synopsis

Analyzes the Windows Security event log (live, remote, or an offline .evtx archive) and ranks Event IDs by count and by estimated storage size — useful for understanding why a log is filling up or wrapping quickly.

Rate calculation Each ranked row includes an average and peak events-per-second figure, computed with the same bucket math as Get-ZNSecurityEventRate (Get-ZNBucketedRate), from timestamps collected during the same single read pass — no second query against the log is needed, and it works against offline .evtx files too. Peak is reported at 1-minute granularity.
Zero Networks-required Event IDs Event IDs that Zero Networks segmentation depends on for enforcement, discovery, or audit evidence are marked with * in both tables and in the CSV export (column ZNRequired) — those audit subcategories must stay enabled even if this analysis shows them as high-volume. The list is maintained in $script:ZNRequiredEventIds (see the Author Reference).

Syntax

Live local log (default)Get-ZNSecurityLogAnalysis [-TopN <int>] [-MaxEvents <long>] [-SampleSize <int>] [-Hours <int>] [-ExportCsv <string>]
Offline archiveGet-ZNSecurityLogAnalysis -LogPath <string> [-TopN <int>] [-MaxEvents <long>] [-SampleSize <int>] [-ExportCsv <string>]
Remote live logGet-ZNSecurityLogAnalysis -ComputerName <string> [-TopN <int>] [-MaxEvents <long>] [-SampleSize <int>] [-Hours <int>] [-ExportCsv <string>]

Parameters

-LogPath

Path to an offline .evtx archive. Mutually exclusive with -ComputerName. Not limited to the Security log — any .evtx is accepted, and IDs from the System log and the Windows Firewall With Advanced Security log are already recognized in the description/required-ID tables.

-TopN

Number of top Event IDs to display per table. Default: 25. Range: 1–100.

-MaxEvents

Maximum events to read. Default: 500000. Use 0 to read the entire log — slow on large files. Rate, count, and size figures are only as accurate as the events actually read.

-SampleSize

Number of events per Event ID to XML-sample for size estimation. Default: 100. Range: 5–1000.

-Hours

Restrict to events from the last N hours. Live log only (local or -ComputerName). Default: 0 (all events currently in the log).

-ComputerName

Remote computer whose live Security log to query. Requires WinRM/RPC access. Mutually exclusive with -LogPath.

-ExportCsv

Writes the full result set (all Event IDs, not just Top N) to this CSV path, including AvgPerSec, PeakPerSec, and ZNRequired columns.

Output

Two console tables — Top N by count (with rate columns) and Top N by estimated size — plus a cumulative-coverage breakdown (how many Event IDs account for 50/80/95% of all events) and general audit policy guidance. With -ExportCsv, every observed Event ID (not just the displayed Top N) is written to CSV.

Examples

Example 1 Local live log, defaults 
PS> Get-ZNSecurityLogAnalysis
Analyzes the local live Security log with default settings (Top 25, 500k event cap).
Example 2 Offline archive 
PS> Get-ZNSecurityLogAnalysis -LogPath "E:\Logs\Archive-Security-2026-07-05.evtx"
Analyzes an offline archive exported from another machine.
Example 3 Full 24-hour analysis 
PS> Get-ZNSecurityLogAnalysis -Hours 24 -MaxEvents 0 -TopN 30
No event cap, last 24 hours, showing the top 30 Event IDs per table.
Example 4 Remote DC with CSV export 
PS> Get-ZNSecurityLogAnalysis -ComputerName "DC01.corp.local" -ExportCsv "C:\Temp\DC01.csv"
Queries a remote DC and writes the full result set to CSV.
Example 5 Batch multiple archives 
PS> Get-ChildItem *.evtx | ForEach-Object {
    Get-ZNSecurityLogAnalysis -LogPath $_.FullName -ExportCsv "$($_.BaseName).csv"
}
Runs the analysis against every .evtx file in the current directory.

Sync-ZNADUserStatus

Identity Sync Destructive R/W API Key Required

Synopsis

Syncs disabled Active Directory accounts to inactive status in the Zero Networks platform. One-directional: AD disabled → ZN inactive. Does not reactivate users.

Requirements Requires the ActiveDirectory PowerShell module (RSAT) and a ZN API key with write scope. Install RSAT with:
Add-WindowsCapability -Online -Name Rsat.ActiveDirectory.DS-LDS.Tools~~~~0.0.1.0
Matching strategy Users are matched by SID (primary key). If no SID match is found, the UserPrincipalName is used as a fallback. Only users with source = Active Directory in ZN are considered.
AD disabled date Active Directory does not store a dedicated "disabled on" timestamp. The whenChanged attribute (last-modified date) is carried into the ZN audit comment as the closest available proxy. It is labeled AD whenChanged in the audit entry, not "disabled on", to be accurate.

Syntax

Sync-ZNADUserStatus [-ApiKey <string>] [-ApiUrl <string>] [-Domain <string>] [-Server <string>] [-Credential <PSCredential>] [-SearchBase <string>] [-Since <datetime>] [-BatchSize <int>] [-Note <string>] [-PassThru] [-WhatIf] [-Confirm]

Parameters

-Domain

AD domain name to query. Defaults to the current user's domain.

-Server

Specific domain controller FQDN to target. Takes precedence over -Domain.

-Credential

PSCredential for the AD query when alternate credentials are required.

-SearchBase

AD OU distinguished name to scope the query (e.g., 'OU=Users,DC=corp,DC=example,DC=com'). Without this the entire domain is scanned. Strongly recommended for large directories to reduce AD query time and result set size.

-Since

Only process AD accounts with whenChanged on or after this date. Use for incremental runs after an initial full sync. Running with -WhatIf will automatically suggest the correct date based on the most recent previous sync detected in the ZN audit log.

Caution: accounts disabled before this cutoff that were not captured in a previous sync will be skipped.

-BatchSize

Number of users per bulk inactivation API call. Default: 100. Range: 1–400. Each batch produces one ZN audit entry with a shared comment containing the whenChanged date range for the users in that batch. Increase toward 400 for very large inactivation sets.

-Note

Admin note appended to each batch's ZN audit comment (e.g., "Q2 offboarding").

-PassThru

Emit one result object per user to the pipeline. The console table is capped at 100 rows; use -PassThru to retrieve the full result set for reporting or further filtering.

-WhatIf

Shows what would be inactivated without making any API calls. Displays the results table, summary, and a Performance Recommendations section — including last-sync date detected from the ZN audit log, -SearchBase and -Since suggestions, and projected API call count.

Output

Displays a results table followed by a summary line. The summary always shows a count for each action category.

ActionMeaning
InactivatedUser was disabled in AD and has been marked inactive in ZN.
Would inactivateWhatIf mode — user would be inactivated on a live run.
Already inactiveUser is disabled in AD and already inactive in ZN — no action taken.
Not found in ZNUser is disabled in AD but has no matching record in ZN.
FailedAPI call for this user failed. A warning is written; other users continue processing.

With -PassThru, each user is emitted as an object with these properties:

PropertyDescription
NameDisplay name or SAMAccountName.
DomainDomain derived from ZN record or UPN.
ADModifiedAD whenChanged date (yyyy-MM-dd) — closest proxy for disable date.
ZNStatusZN status before the sync: Active, Inactive, or — (not in ZN).
ActionOutcome: Inactivated, AlreadyInactive, NotInZN, Failed, or WouldInactivate.
ZNUserIdZN user ID, or $null if not found in ZN.
SIDAD Security Identifier used for matching.

ZN audit comment format

Each batch produces one ZN audit entry. The comment records the whenChanged date range of the users in that batch, plus any -Note text.

Single user in batch: AD sync | AD whenChanged: 2025-11-14 | Note: Q2 offboarding Multiple users in batch: AD sync | AD whenChanged range: 2024-06-01 to 2025-11-14 | Note: Q2 offboarding

The Note: segment is omitted when -Note is not provided.

Examples

Example 1 Preview changes 
PS> Sync-ZNADUserStatus -WhatIf
Shows which users would be inactivated. No API calls are made. Safe to run anytime.
Example 2 Live sync with a note 
PS> Sync-ZNADUserStatus -Domain corp.example.com -Note "Q2 offboarding"
Inactivates all matching users in ZN. Each ZN audit entry records the user's AD whenChanged date and the note.
Example 3 Export inactivated users to CSV 
PS> Sync-ZNADUserStatus -PassThru | Where-Object Action -eq 'Inactivated' | Export-Csv offboarded.csv -NoTypeInformation
Runs the sync and writes only the successfully inactivated users to a CSV file.
Example 4 Target a specific DC with alternate credentials 
PS> $cred = Get-Credential
PS> Sync-ZNADUserStatus -Server dc01.corp.example.com -Credential $cred -WhatIf
Queries a specific domain controller with explicit credentials, in preview mode.
Example 5 Scoped incremental sync 
PS> Sync-ZNADUserStatus -SearchBase 'OU=Corp Users,DC=corp,DC=example,DC=com' -Since '2025-11-15' -BatchSize 400
Incremental run scoped to one OU, processing only accounts modified since Nov 15, with maximum batch size for fewest API calls. Typical follow-on command after reviewing WhatIf recommendations.

Asset Browser

Offline Read-only BreakGlass JSON

The BreakGlass asset browser loads a local snapshot of segmented asset data — the segmentedAssets.json file maintained by the Zero Networks BreakGlass installation — into session memory and exposes it as queryable PowerShell objects. It's basically a fancy ConvertFrom-Json with some added enrichment and helper functions for common queries. No API calls are made after the initial load. All query functions return objects — pipe them freely with Where-Object, Group-Object, Export-Csv, and so on.

All commands in this section use the ZNBG noun prefix to clearly distinguish them from API-backed ZNTools commands.

Workflow Run Import-ZNBGAssetData once per session. The data stays in memory until you re-import or close the session. All query commands below will throw if called before Import-ZNBGAssetData.

Import-ZNBGAssetData

Loads segmentedAssets.json and switches.json into the ZNTools session.

Import-ZNBGAssetData [-DataPath <string>] [-SwitchesPath <string>]
-DataPath

Path to segmentedAssets.json. Defaults to C:\Program Files\Zero Networks\Breakglass\segmentedAssets.json.

-SwitchesPath

Path to switches.json. Defaults to the same Breakglass installation directory.

Example 1 Load from default path 
PS> Import-ZNBGAssetData
Loads from the Breakglass installation directory on the local machine.
Example 2 Load from a custom path 
PS> Import-ZNBGAssetData -DataPath .\segmentedAssets.json
Loads from the current directory — useful when working with an exported copy.
