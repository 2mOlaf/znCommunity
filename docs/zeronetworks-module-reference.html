ZeroNetworks PowerShell Module

PSGallery API Wrapper PowerShell 5.1+ Preview

The ZeroNetworks module on PowerShell Gallery is the official API client for the Zero Networks platform. It wraps the Zero Networks REST API in 700+ cmdlets covering asset management, rule review, policy configuration, group management, and platform settings. Use it for automation, reporting, and bulk operations against your Zero Networks environment.

Preview module The current release is a preview (0.26.3-preview). Install and update commands require -AllowPrerelease. Cmdlet names and parameters may change between preview versions. Pin a version in production automation with -RequiredVersion.

This module vs. ZNTools

Two PowerShell modules are used alongside Zero Networks. They serve different purposes:

PSResourceGetInstall-PSResource -Name ZeroNetworks -Prerelease

Update-Module -Name ZeroNetworks -Scope CurrentUser -Force -AllowPrerelease

Uninstall

Uninstall-Module -Name ZeroNetworks -RequiredVersion '0.0.19-preview' -AllowPrerelease

Pin a specific version (production automation)

Install-Module -Name ZeroNetworks -RequiredVersion 0.26.3-preview -AllowPrerelease

Verify

Verify install Confirm module loads and show version 
PS> Get-Module -ListAvailable ZeroNetworks | Select-Object Name, Version
Should return the installed version. If nothing is returned, the install did not complete.

Authentication

Setup

Two authentication methods are available. The right choice depends on how your account is configured.

IdP users must use API key If your Zero Networks account authenticates through an Identity Provider (SSO/SAML/OIDC), Connect-ZN is not available to you. Use Set-ZnAPIKey with a token generated from the Zero Networks portal.

Method 1 — Email OTP (non-IdP accounts only)

Connect-ZN Interactive OTP login 
PS> Connect-ZN -Email you@company.com
# Check your email for a one-time code and enter it when prompted
Sends a one-time passcode to the supplied email address. Suitable for interactive sessions.

Method 2 — API key (recommended for automation and IdP accounts)

Set-ZnAPIKey Authenticate with a portal-generated token 
PS> Set-ZnAPIKey -ApiKey "eyJ..."
Set the API key once per session. Generate tokens in the Zero Networks portal under Settings → API. For automation, load the key from a secrets manager or environment variable rather than embedding it in script.
API key from env var Recommended pattern for scripts and pipelines 
PS> Set-ZnAPIKey -ApiKey $env:ZN_API_KEY
Reads the key from the ZN_API_KEY environment variable — consistent with the ZNTools convention and avoids hardcoding credentials in scripts.

Sign out

Disconnect-ZN End the current session 
PS> Disconnect-ZN
Clears the current authentication context. Not required at end-of-script, but useful in interactive sessions when switching accounts.

Discovering Commands

Read-only

The module contains 700+ cmdlets. Use Get-Command and Get-Help to explore.

List all cmdlets See everything the module exports 
PS> Get-Command -Module ZeroNetworks | Sort-Object Name
Useful for exploring the full surface area of the module. Pipe to | Out-GridView for a searchable window.
Find by noun Search by functional area 
PS> Get-Command -Name '*ZNAsset*'      # all asset commands
PS> Get-Command -Name '*ZNGroup*'      # group management
PS> Get-Command -Name '*ZNSetting*'    # platform settings
PS> Get-Command -Name 'Approve-ZN*'    # all approval cmdlets
PS> Get-Command -Name '*Mfa*'          # MFA policy cmdlets
The naming pattern is Verb-ZN<Noun>. Common nouns: Asset, Group, Rule, Policy, Setting, Label, User, Tag.
Get-Help Read parameter documentation and examples 
PS> Get-Help Get-ZNAsset -Full
PS> Get-Help Approve-ZNAssetInboundRuleReview -Examples
Every cmdlet has comment-based help with parameter descriptions and at least one example. -Examples is the fastest way to see intended usage.

Asset Search & Discovery

Read-only

Most operations start with resolving an asset identity. Use Search-ZNAsset to find an asset by FQDN, then pass its ID to other cmdlets.

Example 1 Find an asset by FQDN 
PS> $asset = Search-ZNAsset -Fqdn "dc01.contoso.local"
PS> $asset
Returns an asset identity object. The .AssetId property is used as input to most other cmdlets.
Example 2 List assets (first page) 
PS> (Get-ZNAsset -Limit 50).Items | Select-Object Name, Fqdn, AssetStatus
Returns up to 50 assets. The response wraps results in an .Items property. Use -Offset for subsequent pages — see Pagination.
Example 3 Get detailed properties for a specific asset 
PS> $asset = Search-ZNAsset -Fqdn "server01.contoso.local"
PS> Get-ZNAsset -AssetId $asset.AssetId
Retrieves the full asset object including health state, segmentation status, and platform metadata.
Example 4 List all assets (full enumeration) 
PS> $all = [System.Collections.Generic.List[object]]::new()
PS> $limit = 400; $offset = 0
PS> do {
      $page = (Get-ZNAsset -Limit $limit -Offset $offset).Items
      $all.AddRange($page)
      $offset += $page.Count
PS> } while ($page.Count -eq $limit)
PS> "Total assets: $($all.Count)"
Paginates through the full asset inventory. Suitable for reporting scripts or feeding asset IDs into bulk operations.
Example 5 View asset audit history 
PS> $asset = Search-ZNAsset -Fqdn "dc01.contoso.local"
PS> (Get-ZNAssetAudit -AssetId $asset.AssetId).Items | Select-Object -First 20
Returns the audit log for a specific asset, showing policy changes, segmentation events, and administrator actions.

Rule Review & Approval

Write

Zero Networks generates rules via machine learning and queues them for review. The module provides cmdlets to enumerate pending rules and approve or deny them, optionally modifying parameters before approval.

Example 1 List inbound rules for an asset 
PS> $asset = Search-ZNAsset -Fqdn "dc01.contoso.local"
PS> (Get-ZNAssetInboundRule -AssetId $asset.AssetId).Items | Format-Table -AutoSize
Returns all inbound rules associated with the asset. Add -AddBuiltins to include global rules, or -AddAncestors to include rules inherited from group membership.
Example 2 Approve an inbound rule as-is 
PS> $asset = Search-ZNAsset -Fqdn "dc01.contoso.local"
PS> Approve-ZNAssetInboundRuleReview -AssetId $asset.AssetId `
      -RuleId "9d275288-4fc3-46e5-a5a0-ff0626214b87"
Approves the rule without modification. The rule becomes active immediately after approval.
Example 3 Approve with expiry and a review comment 
PS> $expiry = ConvertTo-ZNEpochMS -Date ((Get-Date).AddDays(90))
PS> Approve-ZNAssetInboundRuleReview -AssetId $asset.AssetId `
      -RuleId     "e4a170be-c192-414a-9d36-380a4483583a" `
      -ExpiresAt  $expiry `
      -Reason     "Other" `
      -Details    "Approved for 90 days per change request CHG-1042"
Uses ConvertTo-ZNEpochMS to build the expiry timestamp. Review comments are visible in the portal audit log.
Example 4 Deny a rule 
PS> Deny-ZNAssetInboundRuleReview -AssetId $asset.AssetId `
      -RuleId  "b49360ce-3b4b-4e67-a613-42d4704d097f" `
      -Reason  "Other" `
      -Details "Denied — traffic pattern not expected from this host"
Marks the rule as denied. The traffic will not be permitted.
Example 5 Review outbound rules 
PS> $asset = Search-ZNAsset -Fqdn "workstation01.contoso.local"
PS> (Get-ZNAssetOutboundRule -AssetId $asset.AssetId -AddBuiltins).Items |
      Where-Object Status -eq "Pending" |
      Select-Object RuleId, Description, CreatedAt
Filters to only pending outbound rules. The same Approve-ZNAssetOutboundRuleReview / Deny-ZNAssetOutboundRuleReview pattern applies.

Labels

Write

Labels are key-value tags attached to assets. They drive policy targeting and reporting segments.

Example 1 Add a label to an asset 
PS> $asset = Search-ZNAsset -Fqdn "server01.contoso.local"
PS> Add-ZNAssetLabel -AssetId $asset.AssetId `
      -Labels @(@{ key = "Environment"; value = "Production" })
Labels are key-value pairs. Pass multiple labels as an array of hashtables.
Example 2 Bulk-label assets from a CSV 
PS> Import-Csv assets.csv | ForEach-Object {
      $asset = Search-ZNAsset -Fqdn $_.Fqdn
      Add-ZNAssetLabel -AssetId $asset.AssetId `
          -Labels @(@{ key = "Tier"; value = $_.Tier })
PS> }
CSV columns: Fqdn, Tier. Useful for initial classification of a large asset inventory.

Groups & Users

Write
Example 1 Add an asset to a custom group 
PS> Add-ZNCustomGroupsMember -GroupId "<group-id>" -MembersId @($asset.AssetId)
Use Get-ZNCustomGroups to find the group ID first.
Example 2 Assign an asset manager 
PS> $asset = Search-ZNAsset -Fqdn "server01.contoso.local"
PS> Add-ZNAssetManager -AssetId $asset.AssetId -ManagerIds @("<user-id>")
Asset managers receive notifications for rule reviews on the assets they manage. Use Get-ZNUser to resolve user IDs.

Patterns

Reference

Pagination

All list cmdlets return a wrapper object. Results are in the .Items property. Use -Limit (max results per call) and -Offset (skip count) to paginate. The default limit is 10; the practical maximum is 400.

Pagination pattern Collect all results across pages 
$all = [System.Collections.Generic.List[object]]::new()
$limit = 400; $offset = 0
do {
    $page = (Get-ZNAsset -Limit $limit -Offset $offset).Items
    $all.AddRange($page)
    $offset += $page.Count
} while ($page.Count -eq $limit)
The loop exits when a page returns fewer results than the limit, indicating the last page. Swap Get-ZNAsset for any list cmdlet.

Timestamps

Parameters that accept dates (such as -ExpiresAt) expect epoch milliseconds. Use the bundled helper:

ConvertTo-ZNEpochMS Build timestamp parameters 
# 90 days from now
$expiry = ConvertTo-ZNEpochMS -Date ((Get-Date).AddDays(90))

# Specific date
$expiry = ConvertTo-ZNEpochMS -Date (Get-Date "2026-12-31")
Always use this helper rather than calculating epoch timestamps manually — it handles UTC conversion correctly.

Multi-tenant / MSP

If you manage multiple customer tenants, use -AccountName to target a specific account. When omitted, the account is derived automatically from the token's JWT audience.

-AccountName Target a specific customer account 
PS> Get-ZNAsset -AccountName "customer-tenant-id" -Limit 50
-AccountName is available on virtually every cmdlet. It is optional for single-tenant deployments.

Scripting patterns

Background jobs Run long operations asynchronously 
# Many write cmdlets accept -AsJob
$job = Approve-ZNAssetInboundRuleReview -AssetId $asset.AssetId `
    -RuleId $ruleId -AsJob
Wait-Job $job | Receive-Job
Use -AsJob when approving or modifying many rules in sequence to avoid blocking the session.
Error handling Catch API errors in automation 
try {
    $asset = Search-ZNAsset -Fqdn "unknown.contoso.local"
} catch {
    Write-Warning "Asset lookup failed: $($_.Exception.Message)"
}
API errors surface as terminating exceptions. Wrap bulk operations in try/catch and log failures to a list rather than aborting the whole script.
Bulk approval from a list Approve a set of known rule IDs 
$ruleIds = @(
    "9d275288-4fc3-46e5-a5a0-ff0626214b87",
    "e4a170be-c192-414a-9d36-380a4483583a"
)
$asset = Search-ZNAsset -Fqdn "dc01.contoso.local"
$failed = @()

foreach ($id in $ruleIds) {
    try {
        Approve-ZNAssetInboundRuleReview -AssetId $asset.AssetId -RuleId $id
        Write-Host "Approved $id" -ForegroundColor Green
    } catch {
        $failed += $id
        Write-Warning "Failed $id`: $_"
    }
}
Write-Host "Done. $($failed.Count) failure(s)."
Collects failures without aborting. Review the $failed array after the loop.

Notes & caveats

  • The module is currently in preview. Cmdlet signatures may change between versions. Pin -RequiredVersion in production scripts and test upgrades before rolling out.
  • API token permissions vary by token type. Some cmdlets require a read/write token; read-only tokens will return a Permission Denied error on write operations. Generate tokens at the correct permission level for the task.
  • Rate limiting applies on the Zero Networks API. For bulk operations over large asset sets, add a short Start-Sleep -Milliseconds 100 between iterations if you observe throttling errors.
  • AssetId vs. Fqdn — Most cmdlets require an asset ID (a GUID), not an FQDN. Always resolve via Search-ZNAsset -Fqdn first and cache the result rather than calling Search on every iteration of a loop.
  • Response object structure — List cmdlets wrap results in a response object. Always access .Items to get the actual array: (Get-ZNAsset).Items.
  • Source — GitHub: https://github.com/zeronetworks/zero-powershell. The /src/ZN/docs folder has a markdown file for every cmdlet.
  • Support — support@zeronetworks.com or open an issue on the GitHub repository.
