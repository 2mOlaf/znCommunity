zn-approve.py

Python 3 CLI Tool Rules

A Python 3 command-line tool for reviewing and approving Zero Networks inbound rules. Supports interactive paginated selection, bulk approval, and targeted apply-from-file workflows.

This is a Python script, not a PowerShell script. Unlike most tools in this repository, zn-approve.py runs with python (or python3 on Linux/macOS) rather than PowerShell. It requires Python 3.8 or higher and the requests library. No PowerShell or Zero Networks PowerShell module is needed.

Prerequisites

RequirementDetails
Python 3.8+ Verify with python --version or python3 --version. Download from python.org.
requests library Only external dependency. Install with pip install requests. All other imports are standard library.
Zero Networks API key A read/write JWT token from your Zero Networks portal. Set as ZN_API_KEY environment variable or pass via --api-key.
Network access Outbound HTTPS (port 443) to your Zero Networks portal endpoint.
SetupInstall the dependency and verify
$ pip install requests
$ python zn-approve.py --help

Authentication

The script reads your API key from the ZN_API_KEY environment variable by default. You can also pass it directly with --api-key on any command or globally.

The API key is a JWT. The script decodes it locally (no network call) to extract the aud (audience) claim and construct the correct portal base URL automatically. If the key cannot be decoded as a JWT, the script falls back to https://portal.zeronetworks.com/api/v1.

MethodExample
Environment variable (recommended) $Env:ZN_API_KEY = "eyJ..." (PowerShell)
export ZN_API_KEY="eyJ..." (bash)
Inline flag python zn-approve.py --api-key eyJ... list
Token auto-detection The script decodes the JWT payload to find your account-specific portal URL. You do not need to configure a base URL — it is derived from the token you already have. Use --token-info to inspect what the script sees in your token.

Global Flags

These flags can be passed before or without a subcommand.

--api-key

Your Zero Networks JWT token. Overrides the ZN_API_KEY environment variable. Accepted on the top-level parser and also on each subcommand independently.

Type:String
Required:Optional (if ZN_API_KEY is set)
--token-info

Decodes the active JWT token and prints its claims: audience, subject, name, scope, issued-at, expiry, and issuer. Timestamps are shown in ISO 8601 UTC format. Useful for verifying you have the right key and that it has not expired. Cannot be combined with a subcommand.

Type:Flag (no value)
--connectivity

Makes a test API call (GET /protection/rules/inbound?_limit=1) and prints the HTTP response code. Use this to confirm network access and token validity before running bulk operations. Cannot be combined with a subcommand.

Type:Flag (no value)
--debug

Prints the HTTP method, URL, and response status for every API call. On failures, also prints response headers and the first 500 characters of the response body. Accepted on the top-level parser and on each subcommand.

Type:Flag (no value)

list

Python 3 Read-only

Synopsis

Lists inbound rules with suggestionType=1 (rules suggested for approval). Without --select, prints each rule to the console. With --select, opens an interactive paginated browser where you can mark rules and save their IDs to a file for later use with apply.

Arguments

--select

Opens the interactive selection mode. Rules are displayed page by page; you mark rules using number ranges and save the selected IDs to a file. See Interactive selection mode for the full command reference.

Type:Flag (no value)
Default:Off — non-interactive list to console
--output

Path for the rule ID file written when you run save in interactive mode. One rule ID per line.

Type:String (file path)
Default:zn-approved-rules-YYYY-MM-DD.txt in the working directory
--page-size

Number of rules to display per page in interactive selection mode.

Type:Integer
Default:5

Examples

Example 1Print all pending rules to console
$ python zn-approve.py list
Fetches up to 100 inbound rules with suggestionType=1 and prints source, destination, protocol, and port for each.
Example 2Open interactive selection (default output file)
$ python zn-approve.py list --select
Opens paginated interactive mode. When you save, IDs are written to zn-approved-rules-YYYY-MM-DD.txt.
Example 3Interactive selection with custom output and page size
$ python zn-approve.py list --select --output my-selection.txt --page-size 10

approve-all

Python 3 Writes to API

Synopsis

Fetches all inbound rules in a pending state, prompts for confirmation, then approves them all in sequence. Use --dry-run to preview which API endpoints would be called without making any changes.

Confirmation required This command always prompts Approve ALL N pending rules? (yes/no) before making any changes. Type yes exactly to proceed; anything else cancels.

Arguments

--dry-run

Prints the HTTP method and endpoint URL that would be called for each rule, without making any API calls. Use this to audit scope before committing.

Type:Flag (no value)

Examples

Example 1Preview what would be approved
$ python zn-approve.py approve-all --dry-run
Prints each PUT /protection/rules/inbound/review/approve/{id} that would be called. No changes are made.
Example 2Approve all pending rules
$ python zn-approve.py approve-all
Approve ALL 23 pending rules? (yes/no): yes
Approving 23 rules...
[1/23] Approved rule a1b2c3...
...
Confirms scope, then approves each rule in sequence with a 300ms pause between calls to avoid rate limiting.

apply

Python 3 Writes to API

Synopsis

Approves a specific list of rule IDs, supplied either as a comma-separated string or as a file (one ID per line). This is the second step of the select-then-apply workflow — you review rules with list --select, save your selection, then apply it here.

Confirmation required Always prompts Approve N selected rules? (yes/no) before calling the API.

Arguments

--ids-file

Path to a plain-text file containing one rule ID per line. Empty lines are ignored. Duplicate IDs are deduplicated automatically. This is the output file produced by list --select.

Type:String (file path)
Required:Required if --ids is not provided
--ids

Comma-separated list of rule IDs to approve directly. Can be combined with --ids-file; duplicates across both sources are removed.

Type:String (comma-separated)
Required:Required if --ids-file is not provided
--dry-run

Prints the API method and endpoint for each rule without making any changes.

Type:Flag (no value)

Examples

Example 1Apply a saved selection file
$ python zn-approve.py apply --ids-file zn-approved-rules-2026-06-05.txt
Example 2Dry-run a file before applying
$ python zn-approve.py apply --ids-file zn-approved-rules-2026-06-05.txt --dry-run
Prints each PUT endpoint that would be called. No API changes are made.
Example 3Approve two specific rule IDs inline
$ python zn-approve.py apply --ids "a1b2c3d4,e5f6g7h8"

Recommended Workflow: Select then Apply

The intended use for most situations. Review rules interactively, save only those you want to approve, then apply them in a separate step with confirmation.

  1. Verify your token
    python zn-approve.py --token-info — confirm the key is valid and shows the right portal audience.
  2. Check connectivity
    python zn-approve.py --connectivity — confirms the API is reachable and the token is accepted.
  3. Browse and select rules
    python zn-approve.py list --select — opens the interactive browser. Page through rules, mark the ones you want, then save to write IDs to a file.
  4. Review the saved file
    Open zn-approved-rules-YYYY-MM-DD.txt in any text editor. Remove any IDs you changed your mind about.
  5. Dry-run first
    python zn-approve.py apply --ids-file zn-approved-rules-YYYY-MM-DD.txt --dry-run — confirm the endpoint list looks right.
  6. Apply
    python zn-approve.py apply --ids-file zn-approved-rules-YYYY-MM-DD.txt — type yes at the prompt to approve.

Bulk Workflow: Approve All Pending

For environments where all pending rules are expected to be approved without manual review.

  1. Preview scope
    python zn-approve.py approve-all --dry-run — see every rule ID and endpoint that would be called.
  2. Approve
    python zn-approve.py approve-all — type yes at the prompt.

Interactive Selection Mode Reference

Entered when you run list --select. Rules are shown in pages; each rule is numbered starting at 1. A [*] marker indicates the rule is currently selected.

CommandAliasEffect
nnextGo to the next page
pprevGo to the previous page
s <ranges>—Select rules by number. Accepts comma-separated numbers and ranges (e.g. s 1,3,5-8)
u <ranges>—Unselect rules by number using the same range syntax
aallSelect all rules on the current page
cclearClear all selections across all pages
save—Write the selected rule IDs to the output file (can be done mid-session; selections are preserved)
quit—Exit without saving
Range syntax Ranges are inclusive on both ends. s 1-3,7,10-12 selects rules 1, 2, 3, 7, 10, 11, 12. You can save multiple times during a session — each save overwrites the previous file with the current selection. Your selections persist across page navigation until you clear or quit.

Rate Limiting

The script automatically handles HTTP 429 Too Many Requests responses by waiting 5 seconds and retrying the same request once. Additionally, bulk approval operations (approve-all and apply) insert a 300ms pause between each approval call to reduce the chance of hitting rate limits at scale.

Exit Codes

CodeCondition
0Successful completion (including "no rules found" and user-cancelled confirmations)
1ZN_API_KEY not set and --api-key not provided
