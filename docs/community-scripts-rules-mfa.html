Rules & MFA Scripts

PowerShell Python Community ZN API

Community scripts for managing Zero Networks inbound and outbound rules, approving proposed rule deletions, updating block rules from external data sources, and managing MFA reactive policies.

API key scope All scripts in this section require a read/write Zero Networks API key. The approve-delete scripts perform destructive operations — test with -WhatIf or --dry-run first.

Approve-ZNProposedDeletes.ps1

PowerShellDestructive
🔗 View on GitHub

Synopsis

Fetches all inbound rules in proposed delete state and approves their deletion. Can be scoped to inactive-asset rules only or zero-hit rules only.

Warning Approving rule deletions is irreversible. Always run with -WhatIf first to preview which rules would be affected.

Parameters

-ApiKey

Zero Networks read/write API key. The key is JWT-decoded to determine the account's portal hostname automatically.

Required:True
-WhatIf

Simulates deletions without calling the approve-delete endpoint. Prints which rules would be approved.

Type:Switch
-InactiveAssetsOnly

Limits approval to rules whose suggestion reason is "references an inactive asset(s)".

Type:Switch
-NoHitsOnly

Limits approval to rules whose suggestion reason is "has not been used in the last 6 months".

Type:Switch
Example 1Preview all proposed deletions (dry run)
PS> .\Approve-ZNProposedDeletes.ps1 -ApiKey eyJ... -WhatIf
Prints all rules that would be approved for deletion without making any API calls to the approve-delete endpoint.
Example 2Approve only zero-hit rules
PS> .\Approve-ZNProposedDeletes.ps1 -ApiKey eyJ... -NoHitsOnly
Approves deletion only for rules flagged as unused in the last 6 months. Rules referencing inactive assets are not affected.
Example 3Approve rules for inactive assets only
PS> .\Approve-ZNProposedDeletes.ps1 -ApiKey eyJ... -InactiveAssetsOnly

Update-ZNBlockRulewithRiskyIps.ps1

PowerShellBlock Rules
🔗 View on GitHub

Synopsis

Queries network activities from the previous 24 hours filtered by high-risk source IP and blocked state, then appends any new source IPs to an existing inbound block rule.

Configuration (edit at top of script)

VariableDescription
$APIKeyZero Networks API key
$blockRuleIdID of the inbound block rule to update. Find in the portal URL when viewing the rule.
The script fetches activities with srcRiskLevel=2 (high) and state=3 (blocked), collects unique source asset IDs, and adds any not already in the block rule. It does not remove existing entries.

Update-ZNOutboundBlockfromURLFile.ps1

PowerShellBlock Rules
🔗 View on GitHub

Synopsis

Reads a list of domain names or wildcard patterns from a text file and replaces the remote entity list of an outbound block rule with those URLs.

Configuration

VariableDescription
$APIKeyZero Networks API key
$blockRuleNameDescription of the outbound block rule to find (default: "Block Bad Domain URLs")
$badURLFilePathPath to text file with one URL/pattern per line
URLs beginning with * are encoded as wildcard entries (b:18*url). Exact domain matches use b:17url. The outbound block rule must already exist in the portal before running this script.

Update-mfaPolicies.ps1

PowerShellMFA
🔗 View on GitHub

Synopsis

Audits all inbound reactive (MFA) policies and optionally updates any that have useDefaultIdp = false to use the default IdP. Prompts for confirmation before applying changes.

Parameters

-baseURI

API base URL including the environment subdomain, e.g. https://zncustlabs-admin.zeronetworks.com/api/v1/.

Required:True
-APIKey

Zero Networks API key.

Required:True
-envID

Environment ID, sent as the zn-env-id request header.

Required:True
-DryRun

Reports what would be changed without modifying any policies.

Type:Switch
Example 1Dry-run — show policies that would be updated
PS> .\Update-mfaPolicies.ps1 -baseURI "https://zncustlabs-admin.zeronetworks.com/api/v1/" -APIKey eyJ... -envID env123 -DryRun
Example 2Apply updates interactively
PS> .\Update-mfaPolicies.ps1 -baseURI "https://zncustlabs-admin.zeronetworks.com/api/v1/" -APIKey eyJ... -envID env123
Fetches all policies, shows the percentage with useDefaultIdp=false, then prompts Y/N before updating.

getSecretMicrosoftAuth.ps1

PowerShellMFAMicrosoft Graph
🔗 View on GitHub

Synopsis

Generates a new client secret for the Azure Multi-Factor Authentication service principal using Microsoft Graph, and outputs the secret value. Useful for rotating the MFA Push credential used by Zero Networks.

Requirements

RequirementDetails
Microsoft.Graph modulesMicrosoft.Graph.Authentication and Microsoft.Graph.Applications — auto-installed if missing
PermissionsApp registration with Application.ReadWrite.All permission on Microsoft Graph
Secret visibility The new client secret value is only returned once at creation time. Copy it immediately — it cannot be retrieved again after this script exits.
Example 1Generate a new MFA push client secret
PS> .\getSecretMicrosoftAuth.ps1
Connects to Microsoft Graph interactively, creates a new credential on the Azure MFA service principal (appId: 981f26a1-7f43-403b-a875-f8b09b8cd720) with a 2-year expiry, prints the secret, then disconnects.
